# 自举执行语义

本文冻结测试当前 `i8`、`i16`、`i32`、`i64`、`isize`、`u8`、`u16`、
`u32`、`u64`、`usize`、`f32`、`f64` 与 `bool` 子集所需的行为。它是一份
显式执行契约，而不是优化策略。

所选目标及其数据布局是编译器的显式输入。自举目标为
`x86_64-unknown-linux-gnu`，采用小端字节序、64 位指针和 64 位指针对齐。

## 求值

表达式与函数参数从左到右求值。`&&` 和 `||` 短路。条件只接受 `bool`；
整数永远不会转换为真值。

每条语句都要经过名称检查和类型检查，包括运行时不可达的语句。不可达代码会
降低到脱离主图的 IR 块，不能影响活跃控制流。

整数字面量采用外层声明、return、参数或整数表达式所要求的精确整数类型。没有
整数上下文时默认采用 `i32`。上下文字面量定型不是隐式转换：不同整数类型的值
和变量如果没有显式 `as` 转换，永远不能混用。

十进制浮点字面量同样采用上下文要求的精确 `f32` 或 `f64` 类型，并默认采用
`f64`。十进制到二进制的转换直接舍入到目标格式。溢出目标格式的有限字面量会被
拒绝；下溢与非规格化结果允许存在。

## 有符号整数

`i8`、`i16`、`i32` 和 `i64` 分别是 8、16、32 和 64 位二进制补码整数。
`isize` 是宽度等于所选目标指针宽度的二进制补码整数；在自举目标上为 64 位。
加法、减法、乘法和一元取负按类型的二次幂模数回绕。这是已定义行为，不存在
有符号溢出的未定义行为。

除法向零截断。余数符号与被除数相同，并满足：

```text
left == (left / right) * right + (left % right)
```

除以零会 trap。对每种有符号宽度，最小值除以 `-1` 也会 trap，分别是
`-128`、`-32768`、`-2147483648` 和 `-9223372036854775808`。`isize` 在
其目标宽度的最小值上 trap；自举目标上同样是 `-9223372036854775808`。
对应的 remainder 运算对相同输入也会 trap。

移位计数只使用低 `log2(width)` 位：`i8` 使用三位、`i16` 使用四位、`i32`
使用五位、`i64` 使用六位。`isize` 使用其目标宽度对应的规则。左移回绕到
操作数类型；右移为算术右移并保留符号。

顺序比较采用有符号规则。每种整数类型和 `bool` 都分别定义相等比较；这些类型
之间不会隐式比较或转换。

## 无符号整数

`u8`、`u16`、`u32` 和 `u64` 分别是 8、16、32 和 64 位无符号整数。
`usize` 为无符号类型，宽度等于所选目标的指针宽度；自举目标上为 64 位。加法、
减法、乘法和一元取负按类型的二次幂模数回绕。除法与余数使用无符号算术，只在
除数为零时 trap。

左移回绕到操作数类型。右移为逻辑右移并移入零位。移位计数掩码遵循对应有符号
宽度相同的三、四、五、六位规则。顺序比较采用无符号规则。

## 显式整数转换

`i8`、`i16`、`i32`、`i64`、`isize`、`u8`、`u16`、`u32`、`u64` 与
`usize` 中的任意一对都可以显式转换。扩宽时，有符号源执行符号扩展，无符号源
执行零扩展，与目标的有无符号属性无关。缩窄保留低位。同宽类型或有无符号变化
保持位模式。这些转换永远不会 trap。

即使宽度相同，`isize` 仍与定宽有符号类型不同，`usize` 也仍与定宽无符号类型
不同。值不会隐式混用。

涉及 `bool` 或 `void` 的转换会被拒绝。允许转换到相同整数类型，且不产生效果。

## 浮点数

`f32` 和 `f64` 使用 IEEE-754 binary32 与 binary64 表示。每次算术运算都按
声明类型使用“最近值、偶数优先”模式舍入。保留非规格化操作数和结果；有符号零、
无穷与 NaN 遵循 IEEE-754 标量算术。浮点除以零不会 trap。自举入口会屏蔽
浮点异常，并在调用 Luna 代码前显式建立这一环境。

一元取负翻转符号位，包括零、无穷和 NaN。算术运算符为 `+`、`-`、`*`、`/`。
浮点操作数不能使用 `%`、位运算符或移位。

相等与顺序关系采用 IEEE-754 有序比较。如果任一操作数为 NaN，`==`、`<`、
`<=`、`>` 和 `>=` 均为 false，`!=` 为 true。正零与负零比较相等。

`f32` 和 `f64` 是精确且相互独立的类型。它们不会彼此隐式混用，也不会与整数
类型隐式混用。显式浮点转换不属于当前阶段。

## 优化边界

自举编译器不执行优化。它的 stack-homed x86-64 后端是差分测试使用的参考实现。
未来任何优化后端都必须精确复现本契约。
