# 实现路线图

已接受的语言设计与编译器实现状态有意分开。勾选意味着该能力拥有可执行测试。

## M0：直接代码生成的纵向切片

- [x] 带严格告警策略的 C23 项目骨架
- [x] Source manager 与诊断
- [x] 已接受标点、字面量和关键字的 lexer
- [x] 模块单元、函数与 M0 语句子集的 parser
- [x] 对 `i32`、`bool` 和无结果函数的精确检查
- [x] Typed CFG IR 与 verifier
- [x] 最多六个整数参数的直接内部调用
- [x] x86-64 System V stack-homed 后端
- [x] 独立 Linux `_start`
- [x] GoogleTest 单元、负例、IR 快照与可执行 QEMU 测试
- [x] 确定性的差分随机测试与 libFuzzer 前端目标

M0 支持足够的语言能力，可以编译算术函数、局部变量、`if`、`while`、调用以及
返回整数的 `main`。

## M1：已接受的标量语言

- [x] 完整 `i64` 纵向切片，包括 IR、x86-64 ABI 与 trap
- [x] 已实现整数类型之间的显式 `as` 转换
- [x] `u32` 与 `u64` 完整纵向切片及无符号代码生成
- [x] 有符号与无符号宽度共用的类型导向整数 IR
- [x] 所有定宽整数类型
- [x] 目标尺寸 `isize` 与 `usize`
- [x] `f32` 与 `f64`
- [ ] 其余标量与指针类型的显式转换
- [ ] 完整运算符与 `do` / `for` / `switch`
- [ ] 原始指针、定长数组与字符串字面量
- [ ] 外部 C 声明
- [x] 显式目标模型与目标数据布局测试

## M2：聚合类型与模块闭环

- [ ] 结构、联合与有作用域枚举
- [ ] 聚合初始化
- [ ] 模块接口与实现匹配
- [ ] import 可见性与依赖验证
- [ ] 独立编译的模块元数据

## M3：生产级 x86-64 后端

- [ ] 目标 machine IR
- [ ] 活跃性分析
- [ ] 线性扫描寄存器分配
- [ ] 栈参数与聚合 ABI 分类
- [ ] 指令级差分测试
- [ ] 原生 ELF64 可重定位对象写入器
- [ ] 调试信息设计

## M4：自举

- [ ] 最小运行时与标准库
- [ ] 使用 Luna 实现 lexer 与 parser
- [ ] 使用 Luna 实现类型检查与 IR
- [ ] 使用 Luna 实现 x86-64 后端
- [ ] stage 1、stage 2 与 stage 3 可复现性比较

## 明确延期

超出局部 x86-64 改进的优化、通用元编程、并行编译、增量编译、包管理、语言
服务器和非 x86-64 后端都不属于自举路径。
